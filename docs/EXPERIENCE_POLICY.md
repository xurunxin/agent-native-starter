# 经验的生命周期：只记可复用的教训

本文件供初始化后的 Agent 使用；它不是另一份长期任务列表，也不要求每次提交生成报告。**当前经验规则的唯一入口是根目录 LESSONS.md**，历史细节主要由带证据的 Issue/PR 保存。没有必要为每个任务创建 experience 文件。

## 任务开始时

从 AGENTS.md 路由到相关 Skill；快速扫描 LESSONS.md 的活动经验，**只读取与本次子系统/风险相关的条目**。普通编码不需要先总结全仓库事故或计算所有文件哈希。发现与当前任务矛盾的经验，先核对实际代码/环境并在 Issue 或 PR 记录，不得静默绕过安全政策。

## 什么时候记录

| 事件 | 记录到哪里 | 是否晋升长期规则 |
|---|---|---|
| 正常小功能、一次性拼写、常规绿测 | PR 或提交的最短说明 | **不写 LESSONS** |
| 第一次遇到真实回归、错误接口理解、无意义测试/兼容层导致返工 | 原始 Issue/PR 记录触发条件、根因、复现证据及修复 | 暂不晋升，除非高影响 |
| 同类问题在 **两个独立任务**重复，且有明确的可执行预防办法 | 提议一条 LESSONS 活动经验，链接原始证据 | 可信审查后加入；不自动创建更多流程 |
| 同一条经验在多个任务得到验证，跨项目/子系统均适用 | 通过独立 PR 合并到 docs/engineering.md 或相关子系统 reference | 提升为稳定规则，LESSONS 仅保留引用 |
| 密钥泄露、权限越界、数据丢失等严重事件 | 立即转为安全/治理 Issue 并通知授权维护者 | 不等待重复；增强防护需要授权 |

## LESSONS 活动条目格式

每条**不超过 6 个短句**，只写：
- **触发**：什么真实条件会遇到；
- **做法**：下一次 Agent 要执行的具体动作；
- **原因**：曾经失败的可复现根因，区别于猜测；
- **证据**：Issue/PR/测试链接；
- **范围**：具体系统和阶段；不得无条件推广；
- **复核**：下次在何时/因何情况检查其有效性。

不要重复粘贴完整 CI 日志、长堆栈、每日时间线、SHA 列表。跟任务相关的调试笔记放到 PR 对话而不是 README/AGENTS。永久兼容义务仍由发布/接口参考管理，不因为压缩经验而删除。

## 何时总结、压缩与退出

正常结束一个任务时，Agent 只需检查“是否发现新且可能复发的教训”，**没有则无需写文件**。在里程碑/版本稳定化、交接前，或当 LESSONS 活动条目**超过 12 条或 120 行**时，调用 learning-loop 做一次小规模清理：

1. 合并重复规则，只留下当前可执行的短句和证据链接；
2. 检查已经修复的根因是否仍存在。没复发且不再有适用场景的规则，可在受审 PR 中退休；
3. 已经写入 engineering/reference 的经验仅保留链接，避免两处出现不同版本；
4. 历史仍可从对应 Issue/PR/Git 找回，必要时归档到 docs/archive/，不重写旧证据；
5. 每次只维护受影响的经验，**不全仓扫描，也不循环生成多份总结**。

规则失效、项目阶段改变、相关接口改变时立即复核；“到期”只是提醒，不能自动删除高风险保护。未经授权不得降低已有测试、CI、审查或平台权限。

## 每次交接最短信息

记录：**当前实现入口 / 本轮用户行为变化 / 已运行的最小验证 / 仍阻塞的 Issue**。若有新的可复用教训，额外给一个证据链接。新的 Agent 从 AGENTS.md + 相关 Skill + 这份最短交接恢复，不需要阅读逐次调试流水。
