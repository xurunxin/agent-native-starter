# 工程标准

## 任务完成定义
Issue 验收明确，PR 范围一致，关键回归反证通过，CI 结果与被审查的 head SHA 一致，契约变更文档已更新，审查缺陷已解决；发布是另一个独立阶段。

## 提交规范
`scope: 可观察的行为变化 (#issue)`，正文包含触发条件、修改前后、验证命令和未覆盖场景。避免以“修复问题”“优化代码”代替语义说明。

## 验证阶梯
1. 迭代阶段：受影响模块的快速测试。
2. PR 阶段：回归反证、静态检查、涉及子系统的契约测试。
3. 集成阶段：最新 base 上的合并结果、并发/安全/平台相关检查。
4. 发布阶段：真实构建、签名/摘要、冒烟测试、回滚路径及批准。

## 文档分工
- `README.md`：面向使用者，当前可用能力。
- `docs/subsystems/`：当前子系统运行行为和权威源码。
- `docs/adr/`：长期技术决策及权衡。
- Issue：尚未完成的需求/风险/计划。
- PR：本次语义变化及验证证据。
- `LESSONS.md`：事故与反例；成熟通用规则上升到工程标准。

## 风险分类
低：文案、无副作用纯函数、测试增补。中：API 或跨模块契约、并发状态。高：凭证、权限、账务、生产环境、删除/迁移、CI/发布流程、依赖安装脚本。风险未知按高风险处理。
