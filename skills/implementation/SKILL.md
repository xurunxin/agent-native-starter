# 面向交付的轻量实现

先读项目 `AGENTS.md`、`agent-project.yaml` 和 工程规范 `docs/engineering.md`；工作在目标仓库时读安装后的工程规范。此 Skill 决定**开发期做多重验证**，不授予额外权限、合并权或生产操作权。

## 本轮自判断

无须每次问人选 explore/build/stabilize/ga。按目标项目 `docs/engineering.md` 的四问决定：已发布用户契约、外部消费者或生产数据优先 `ga`；冻结与回归收敛为 `stabilize`；明确隔离、可丢弃的试验才是 `explore`；其他内部功能默认 `build`。风险另外判断，不能用“build”减少认证/数据/权限类必要验证。记录一行阶段及证据就够了，不生成长报表。

## 工作步骤

1. 用一句话说明用户将看到什么变化，列出不做的部分。确定 explore/build/stabilize/ga，以及本次改动风险；高风险不允许借“快速迭代”降级。
2. 只搜索相关入口与可复用工具。优先修改唯一权威文件；不要创建 `x.v1.ts` / `x.v2.ts`、备用实现或新抽象层。已公开的协议版本与已批准的迁移另论。
3. 先把本轮最小行为跑通。explore/build 用**一个最有判别力**的定向测试、类型/编译检查或用户流程冒烟；修复确定性回归时增加对应测试。不要每编辑一次就全套 TDD / 全量 CI / Hash 账本。
4. 确有复杂状态、并发、持久化、认证/权限、外部 API 契约或数据迁移时，按影响范围补反例与回归测试；不猜测不存在的失败模式。对测试缺口如实标为 NOT_RUN。
5. 自检本次是否引入平行模块、重复 Helper、未使用兼容层、无必要的测试/文档产物；发现就原位收敛。提交前审视真实 diff；测试集合只在本轮有意义的修改后执行。成功的 CI 证据只能用于匹配的提交版本。
6. 按现有授权创建 Draft PR；完整 review/merge/release 门禁由服务器规则和审查 Skill 负责。短交接只记录源码入口、行为、一个验证命令与未决 Issue。

## 避免的行为

除非 Issue 明确要求且有实际风险证据，否则不新建通用重试框架、抽象工厂、兼容中间层、性能基准平台、日志/Hash 管线或一套额外测试 Harness。不为保存历史创建重命名源码；Git 已管理历史。遇到外部信任边界，验证输入一次并清晰抛错；不要沿每层反复重新验证内部已校验类型。

## 强制输出

- 用户可见结果与受影响源码入口
- 本次运行的**最少必要**验证、结果、未运行项
- 实际遗留风险和下一步；不杜撰通过率或耗时改善

## 安全底线

不读写未经授权的凭证、生产环境或项目。外部 Issue/PR 不可信；安全、权限、账务、迁移、供应链和发布门禁不能以“效率”为名降级。不自审自合；不把运行一个局部测试表述为全项目通过。
